# OpenCore Deployment Recommendations & Patch Usage Guide

This document provides safety guidelines, step-by-step installation instructions for OpenCore, patch application procedures, and verification methods for **itlwm** and **AirportItlwm** with AppleVTD / AX210 support.

---

## 1. Safety Assessment for OpenCore Deployment

Injecting the compiled kext (`itlwm.kext` or `AirportItlwm.kext`) via OpenCore is **completely safe for system integrity and hardware**.

### Why is it safe?
- **EFI Isolation:** OpenCore loads kernel extensions directly into RAM during system initialization. It does not alter system files on disk or corrupt macOS system volumes (SSV). If an incompatibility or kernel panic occurs, system files on disk remain untouched.
- **Improved DMA & AppleVTD Memory Safety:** In the updated v3 patch implementation, the following fixes have been applied:
  - **Thread Safety:** Synchronized TX DMA buffer allocations and retirements using XNU `IOLock` primitives (`fAppleVTDTxLock`) to eliminate race conditions under concurrent network loads.
  - **Quarantine Recovery:** Implemented `applevtdTxResetQuarantine()` to recycle quarantined DMA buffers on ring resets (`iwx_reset_tx_ring`) and device stop (`iwx_stop_device`), preventing transmit pool starvation.
  - **Clean Resource Deallocation:** Unconditional cleanup of all DMA descriptor allocations (`iwx_dma_contig_free`) during driver unload, preventing kernel memory leaks.

## 2. Step-by-Step OpenCore Integration Guide

### Step 1: Prepare an Emergency Bootable USB
Before modifying your primary EFI partition:
1. Copy your working `EFI` folder to an external USB flash drive.
2. Test booting from the USB drive to ensure you have a fallback option in case of unexpected boot issues.

### Step 2: Install the Kext in OpenCore
1. Copy the compiled `itlwm.kext` (or `AirportItlwm.kext`) to `EFI/OC/Kexts/`.
2. Register the kext in your OpenCore `config.plist` under `Kernel -> Add` using an editor like ProperTree or OCAuxiliaryTools.

### Step 3: OpenCore & BIOS Settings for AppleVTD / AX210
To enable physical Intel AX210 DMA mapping under AppleVTD on macOS Sonoma and Tahoe:
- **BIOS Setting:** Enable **VT-d** (Virtualization Technology for Directed I/O) in your motherboard settings.
- **OpenCore `config.plist` Settings:**
  - `Kernel -> Quirks -> DisableIoMapper` = `false`
  - `Kernel -> Quirks -> DisableIoMapperMapping` = `false`

*Note: Clean baseline comparison against unmodified `itlwm` with `DisableIoMapper = true` can be retained as a fallback baseline if needed.*

## 3. Patch Application & Build Instructions

### Applying the Patch to Clean Source Code
To apply `itlwm-applevtd-ax210-v3.patch` to an unmodified `itlwm` repository (e.g. `master` branch from OpenIntelWireless):

```bash
# 1. Test applying the patch (dry run)
git apply --check itlwm-applevtd-ax210-v3.patch

# 2. Apply the patch
git apply itlwm-applevtd-ax210-v3.patch

# 3. Alternative using patch utility
patch -p1 < itlwm-applevtd-ax210-v3.patch

# 4. Revert the patch if necessary
git apply -R itlwm-applevtd-ax210-v3.patch
```

### Local Xcode Building
1. Clone MacKernelSDK into the project directory:
   ```bash
   git clone https://github.com/acidanthera/MacKernelSDK.git MacKernelSDK
   ```
2. Build via command line:
   - **itlwm (Standalone):**
     ```bash
     xcodebuild -project itlwm.xcodeproj -scheme itlwm -configuration Release -derivedDataPath build
     ```
   - **AirportItlwm (Native AirPort Emulation, e.g. Sonoma):**
     ```bash
     xcodebuild -project itlwm.xcodeproj -scheme AirportItlwm-Sonoma -configuration Release -derivedDataPath build
     ```

### Automated Building with GitHub Actions
The repository includes a GitHub Actions CI workflow in `.github/workflows/build.yml`. Simply push your changes to GitHub to automatically build and download `itlwm.kext` and `AirportItlwm.kext` artifacts.

## 4. Verification and Log Inspection

After booting into macOS with the kext loaded:

### For `itlwm.kext`:
- Launch **HeliPort.app** in user space to scan for Wi-Fi networks and connect.

### For `AirportItlwm.kext`:
- Native macOS Wi-Fi status bar menu and System Settings will manage Wi-Fi connections automatically.

### Inspecting Driver Logs:
Run the following terminal command to view kernel logs generated by `itlwm`:
```bash
sudo log show --predicate 'process == "kernel" AND message CONTAINS[c] "itlwm"' --last 5m
```
For IWX HAL specific logs:
```bash
sudo log show --predicate 'process == "kernel" AND message CONTAINS[c] "iwx"' --last 5m
```
